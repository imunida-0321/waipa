# 広告配置リファレンス（AdMob）

WaiPa の広告がどこに・いつ・どの条件で出るかの恒久ドキュメント。
設計の経緯は [superpowers/specs/2026-07-19-admob-ads-design.md](superpowers/specs/2026-07-19-admob-ads-design.md)、実装手順は [superpowers/plans/2026-07-19-admob-ads.md](superpowers/plans/2026-07-19-admob-ads.md) を参照（issue #6）。

## 配置一覧

| 広告                           | 場所                                               | タイミング・条件                                                                                                                                                                          |
| ------------------------------ | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| バナー（アンカーアダプティブ） | ホーム画面の最下部のみ                             | 常時表示。ゲーム中・イントロ・設定・ギャラリーには出さない                                                                                                                                |
| インタースティシャル           | ゲーム → ホームへの退出時                          | play 画面からの退出ごとに毎回（`N=1`）。イントロだけ見て閉じた場合は出さない。ヘッダー戻る・Android 戻るボタン・iOS スワイプバックのどの退出経路でも発火（`beforeRemove` イベントで検知） |
| リワード動画                   | 王様のいない王様ゲームの「限定お題パック」モーダル | 視聴1回で `king_premium` パックを解放。**そのゲームセッション中のみ**（ゲームを出ると再ロック）                                                                                           |
| ATT ダイアログ（iOS）          | 初回起動時・ホーム表示直後                         | AdMob 初期化の前に許可を取得（初回バナーからパーソナライズ広告を出すため）                                                                                                                |

## 共通ルール

- **プレミアム購読者には一切広告を出さない。** 判定源は `src/lib/premium.ts` の `isPremiumUnlocked()` のみ。true のとき: バナー非レンダリング / インタースティシャル no-op / リワードモーダルは「解放中」表示（お題は常時解放）
- インタースティシャルの頻度は `src/constants/ads.ts` の `INTERSTITIAL_EVERY_N_EXITS` で一元管理（初期値 1 = 毎回）。緩める場合はこの定数だけ変える
- インタースティシャルは表示後に自動で次を先読み。ロード失敗（ERROR）時は次の退出タイミングで再読み込みを試みる
- リワードの解放は unlock の前にお題取得の成功を確認する（取得失敗時は unlock せず「再試行」導線を出す。動画の再視聴は不要）

## 運用メモ

- **開発中はテスト広告 ID**（`__DEV__` で `TestIds` に自動切替）。Expo Go では SDK が動かないため、動作確認は dev build（EAS）
- dev build では `isPremiumUnlocked()` スタブが true（= 広告非表示）なので、広告確認時は一時的に `src/lib/premium.ts` を `return false` にする（コミットしない）。恒久対応は #7（RevenueCat）
- **本番切り替え時にやること**:
    1. AdMob コンソールで iOS / Android の2アプリを登録し、App ID を `app.json` の config plugin に設定（要ネイティブ再ビルド）
    2. 広告ユニット（バナー / インタースティシャル / リワード × 2 OS = 6個）を作成し、`src/constants/ads.ts` を本番 ID に差し替え（iOS / Android で ID が異なるため `Platform.select` 化する）
    3. 開発者ドメイン直下に `app-ads.txt` を設置し、ストア掲載のデベロッパーサイト欄をそのドメインにする
    4. リリース後、AdMob コンソールでストア掲載と紐付け（審査完了まで数日〜2週間は配信が制限される。異常ではない）
- 本番ユニット ID を自分の端末で確認する場合は、AdMob コンソールに**テストデバイス登録**してから行う（未登録での連続表示は無効トラフィック扱い＝アカウント停止リスク）
