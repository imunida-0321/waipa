# AdMob 広告実装 設計書（Issue #6）

日付: 2026-07-19
対象 Issue: #6 「#収益1 AdMob 広告実装」
ブランチ: feature/6-admob-ads（develop ベース）

## 目的

収益の主軸となる AdMob 広告（バナー / インタースティシャル / リワード）を実装する。プレミアム購読者には一切広告を出さない。

## 配置の決定事項

| 広告                   | 配置                                       | 条件・頻度                                                       |
| ---------------------- | ------------------------------------------ | ---------------------------------------------------------------- |
| バナー                 | ホーム下部のみ（アンカーアダプティブ）     | 常時表示。プレミアムは非表示                                     |
| インタースティシャル   | プレイ画面からの退出時（ゲーム → ホーム）  | 毎回表示（定数 `N=1`）。イントロだけ見て閉じた場合は表示しない   |
| リワード（お題パック） | 王様のいない王様ゲームの限定パックモーダル | 視聴 1 回で `king_premium` パックを**そのセッション中のみ**解放  |
| ATT（iOS）             | 初回起動時・ホーム表示直後                 | AdMob 初期化前に許可を取得（初回バナーからパーソナライズ広告可） |

### 決定の背景

- **インタースティシャルは「リザルト後」ではなく「退出時」**: 共通のリザルトイベントが存在せず（リザルトは各ゲーム内部管理）、退出時なら `GameScreen` の 1 箇所へのフックで全 16 ゲームに効く。「もう一回」の連続プレイ中に広告が割り込まず、パーティーの流れを切らない。
- **頻度は毎回（N=1）**: issue 記載の「N プレイごと（初期値 3）」は定数化の方針だけ残し、初期値を 1 にする。緩めたくなったら定数変更のみで対応可能。
- **バナーはホームのみ**: ゲーム中は誤タップ事故（連打系ゲーム）、イントロ画面は「閉じる」ボタンとの位置競合と低い視認性のため見送り。退出ごとのインタースティシャルで広告圧は既に十分。
- **リワードは王様ゲームのみ**: `premium-pack-modal.tsx` に接続用スタブが既にある。他ゲームへの横展開は効果を見てから別 issue で判断。
- **解放はセッション単位**: リワード在庫が繰り返し使え、「毎回見るのが面倒なら課金」というプレミアム導線としても機能する。

## 非目標（YAGNI / 別 issue）

- **プレミアムゲームのお試しプレイ**（動画視聴で 2 ラウンド解放 → 以降課金までロック）は別 issue（#6 のリワード基盤と #7 RevenueCat に依存）
- ホーム以外の画面へのバナー表示
- 爆弾リレー / リアクション神経衰弱への限定パック横展開
- Remote Config によるリアルタイム頻度変更（MVP はローカル定数。将来 Supabase 経由で上書き可能な形にしておく）

## 現状

- 全ゲーム共通枠は `src/components/game/game-screen.tsx`（`intro → setup → play` の 3 ステージ）。リザルト通知の共通機構はない。
- プレミアム判定は `src/lib/premium.ts` の `isPremiumUnlocked()`。
- 王様ゲームの `src/games/no-king-game/premium-pack-modal.tsx` が「広告視聴 または プレミアムで解放」の案内スタブ。
- `src/lib/topics-store.ts` は `is_premium=eq.false` のみ取得しており、**プレミアムお題の取得経路が存在しない**。

## 設計

### SDK・初期化フロー

- `react-native-google-mobile-ads`（Expo config plugin / EAS Build。**Expo Go では動作しない**ため動作確認は dev build）
- `expo-tracking-transparency` で ATT 許可取得 → AdMob 初期化、の順を初回起動時に実行
- 開発中はテスト広告ユニット ID を使用

### `src/lib/ads.ts`（広告ロジックの集約）

- 初期化（ATT 後に 1 回）
- プレミアム分岐: `isPremiumUnlocked()` を唯一の判定源とし、true なら全広告 API が no-op になる
- インタースティシャル: プリロード＋退出カウンタ（`INTERSTITIAL_EVERY_N_EXITS = 1` 定数）
- リワード: ロードと視聴完了コールバック

UI 側（ホーム / `GameScreen` / `PremiumPackModal`）は薄い呼び出しのみ。

### 各配置の接続点

- **バナー**: `src/app/index.tsx` のホーム最下部にバナーコンポーネントを追加（セーフエリア考慮）。プレミアム時は非レンダリング
- **インタースティシャル**: `GameScreen` の play ステージからの戻る操作にフック。intro ステージからの閉じるではカウント・表示しない
- **リワード**: `PremiumPackModal` に「動画を見て解放」ボタンを実装。視聴完了で `king_premium` をセッション解放（セッション＝王様ゲームから退出するまで。メモリ上の状態で、ゲームを出たら再ロック）。プレミアム時はモーダル自体を出さずパック解放済み扱い
- **プレミアムお題取得**: `topics-store` に `king_premium` パックの取得経路を追加（解放時またはプレミアム時に取得）

## テスト方針（TDD）

広告 SDK はモックし、以下をユニットテストで担保する。

- 退出カウンタが N 回ごとに表示を要求する（N=1 で毎回）
- intro ステージからの退出ではカウント・表示されない
- プレミアム時はバナー非表示・インタースティシャル/リワードが一切呼ばれない
- リワード視聴完了で `king_premium` がセッション解放され、ゲーム退出で再ロックされる

実機ではテスト広告 ID で表示確認する。
