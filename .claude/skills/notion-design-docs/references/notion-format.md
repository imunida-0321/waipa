# Notion のページの書き方

Notion の Markdown は、ふつうの Markdown に Notion 独自のタグを足したもの。正確な仕様は `notion-fetch` に `notion://docs/notion-flavored-markdown-spec` を渡すと読める。ここには、WaiPa の設計書で使う書き方と、実際につまずいた癖をまとめる。

## ページの骨組み

各ページの先頭には、次の注意書きを置いている。新しいページにも入れる。

```markdown
<callout icon="📌" color="gray_bg">
このページが正です。
</callout>
```

その下は、冒頭の表（画面ID、ルート、実装、種別。ゲームなら人数とお題パックも）、目的または概要、各章の順。既存のページを1つ読んでから書くと、章立てと文体がそろう。

## スクリーンショットの並べ方

スクリーンショットは縦長なので、そのまま置くとページ幅いっぱいに広がって読みにくい。`<columns>` に入れて幅を抑える。

1枚のとき（右に説明文。説明が無ければ `<p />`）:

```markdown
<columns>
<column ratio="30">
<image source="file-upload://<アップロードID>">キャプション</image>
</column>
<column ratio="70">
説明文
</column>
</columns>
```

2枚のとき: `ratio` を 30 / 30 / 40 にして、3列目は `<p />`。

3枚以上のとき: `ratio` を付けずに等分する。

アップロード直後の画像は `file-upload://<ID>` で参照する。保存後に読み戻すと `notion-file-block://...` に変わっている。既存の画像を残したまま本文を直すときは、読み戻した `notion-file-block://...` をそのまま残す。

## リンク

- ページへのリンク: `<mention url="https://app.notion.com/p/<ID>">ページ名</mention>`。表のセルの中でも使える。表示はページ名になる
- リポジトリのファイル: リンクにせず、`docs/ADS.md` のようにコードで書く
- 外部の URL: ふつうの `[文字](URL)`

## 更新のしかた

- 部分修正は `notion-update-page` の `update_content`。`old_str` は、読み戻した本文の文字列と完全に一致させる
- `old_str` が見つからないと、その置き換えは失敗する。読み戻した本文には `<code>` や `\_` が入っていることがあるので、読み戻した表記に合わせる
- 親ページを `replace_content` するときは、子ページの `<page url="...">` タグを全部残す。消すと子ページごと消えそうになり、エラーで止まる

## 癖

- 本文の `_` は、保存時に `\_` へエスケープされることがある。あとで置換するための目印に `_` を含む文字列を使わない
- `` `code` `` は、読み戻すと `<code>code</code>` になる。書くときはバッククォートでよい
- 表は、パイプの表（`| a | b |`）で書けば Notion の表になる
- ページを作るときに本文を空にしておき、あとから `replace_content` で入れると、ページ同士のリンクを先に確定できる（複数のページを一度に作るときに便利）
